# CPI 기준연도 2023 → 2025 변경 (영향 판단 + 실행 안내)

배수 k = CPI 2025 ÷ CPI 2023 = 116.61 ÷ 111.59 = **1.04499** (KOSIS, 2020=100)

## 1. 영향 판단: 결과는 바뀌지 않는다 (표시 금액만 바뀜)

기준연도를 바꾸는 것은 **모든 해의 금액에 같은 상수 k를 곱하는 것**이다. 그래서

| 대상 | 영향 | 이유 |
|---|---|---|
| 빈곤선 | 모두 ×k | 빈곤선이 같은 실질 소득의 중위 50%로 계산되므로 같이 커진다 |
| 정답(지속 하락) | **없음** | 소득 ÷ 빈곤선 비율로 판정 → k가 분자·분모에서 지워진다 |
| 비율 변수 (log_ratio, log_dratio, 2·4년 변화, 최저 소득비, 변동성, 과거 빈곤, 자산·부채 ÷ 소득) | **없음** | 같은 이유 |
| 금액 변수 x_own_earn_l2 | ×k | 표준화(로지스틱)·분위 절단(0.5/99.5%)·트리 분할 모두 배율에 무관 → 모델 결과 같음 |
| 로그 금액 lg_x_* = ln(1+금액) | +ln k ≈ +0.044 (0원은 0 그대로) | 순서가 그대로라 LightGBM은 같은 트리. 로지스틱은 거의 상수 이동이라 표준화로 흡수 (금액 10만원 미만에서만 0.04 이하로 다름) |
| AUC·포착률·판정 | **사실상 없음** (예상 |ΔAUC| < 0.001) | 위 모두 |
| 보고서 표시 금액 | ×k | 빈곤선 표(7쪽), 예시 금액(2쪽) 등 |
| "금융자산 +1,000만원 / +3,000만원" 반사실(29쪽) | **조금 바뀔 수 있음** | 같은 명목 금액이 실질로 4.3% 작아짐 → 다시 계산 필요 |

**미리 확인한 것** (원자료 없이 할 수 있는 범위): 지금 모델에 2025년 가격 금액을 그대로 넣어 봐도(재학습 없이)
일치 테스트 300줄에서 구간이 바뀐 사람 0명, 위험 상위 % 차이 중앙값 0.006%p, 순위 상관 0.9999.
재학습하면 LightGBM은 정의상 같아지므로 차이는 이보다 작다.

## 2. 사전 등록 기준 (재실행 전에 고정)

C1 정답 불일치 0행 · C2 비율 변수 차이 < 1e-9 · C3 금액 변수 = 정확히 ×k · C4 과제별 |ΔAUC| ≤ 0.002, 판정 불변.
미달이면 원인을 찾고 결과는 그대로 보고서에 기록한다. 검증 스크립트: `tools/check_cpi_2025.py`

## 3. 실행 순서 (팀 환경, 원자료 필요)

1. `build_common.py`의 CPI 환산 기준연도를 2023 → **2025**로 바꾼다
   (`금액 × CPI[2025] / CPI[소득연도]`, CSV는 `7_cpi_kosis_2020eq100.csv` 그대로).
2. 데이터를 다시 만들고 최종 모델을 다시 학습한다.
3. `python tools/check_cpi_2025.py 옛.csv 새.csv ...` → C1~C4 확인.
4. (서비스 모델 미리사주 패키지는 constants.json의 CPI·빈곤선으로 화면 금액을 직접 환산하므로 백엔드 수정은 필요 없다.)
5. 보고서 표시 금액을 바꾸고, 29쪽 반사실 표는 다시 계산한 값으로 바꾼다.

## 4. 보고서에서 바꿀 숫자 (×1.04499, 반올림)
